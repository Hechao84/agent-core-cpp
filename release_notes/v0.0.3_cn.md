# 版本 v0.0.3

## 概述

v0.0.3 落地 round5 渐进披露设计文档 §5.4.1 条 1-11 的 V2 阶段：

- 实现 `findRelevant`（LLM-backed capability recall），让 `selective` 模式真正启用——turn 起点跑一次召回种 Tier 1 active set，turn 中途 `tool_search`/`skill_search` 的 search action 走真召回（非 V1 桩）。
- 新建 `CapabilitySelector`（替代被废弃的 `ToolSelector`），使用主 `modelConfig` 做 LLM 召回，输出 `CapabilitySelection{tools, skills}` 一次调用同时选 tool+skill。
- `ToolTurnState` 重命名为 `TurnState`、文件 `tool_turn_state.h` → `turn_state.h`、proxy 同步重命名；接口对称扩 skill 侧 5 个方法（`searchSkill`/`getSkillActiveSet`/`seedSkillActive`/`seedSkillActiveSubset`/`isActiveFullSkillPool`）+ tool 侧 `seedActiveSubset`。
- `SkillEngine::GetSkillCatalog` 新增 by-subset 重载，按 `skillActiveSet` 渲染（镜像 `ResourceManager::GetToolCatalog` 的 by-subset 渲染）。
- `skill_search` 加 `TurnState*` + `CapabilitySelector*` 参数，search action 按 `isActiveFullSkillPool()` 短路信号分支（镜像 tool 侧 §5.3 短路状态通道）。

## 重点更新

### 框架层面

- **`CapabilitySelector`**（新文件 `src/core/capability_selector.{h,cpp}`）：LLM-backed capability 召回，构造时持 `AgentConfig`（复用主 `modelConfig`），按 `ResourceManager::GetToolCatalog` 取 tool desc、按 `SkillEngine::GetSkillCatalog` 取 skill desc（不攒死副本）。`findRelevant(rawQuery, sessionContext) -> CapabilitySelection`，吃 query + `GetContextWindow()` 截断历史，输出 `{"tools":[...],"skills":[...]}` JSON 解析。失败 / 返空 → 返空 `CapabilitySelection`，由 Invoke 入口识别为降级触发条件。
- **`ToolSelector` 废弃**（`src/tools/tool_selector.{h,cpp}` + `unittest/test_tool_selector.cpp` 删除）：V1 双重缺陷——选择方法死（`return 1.0` 桩）、数据通道错（只持 name 不持 desc）。`AgentWorker::toolSelector_` 成员、4 处 `AddToolToPool`/`RemoveToolFromPool` 镜像调用一并删除，等价于直接用 `toolNames_`。
- **`TurnState` 重命名**：`ToolTurnState` → `TurnState`，文件 `tool_turn_state.h` → `turn_state.h`、`tool_turn_state_proxy.{h,cpp}` → `turn_state_proxy.{h,cpp}`。内部头（src/core/，不导出符号），所有消费点（worker_env.h、session_manager.cpp、agent_worker.{h,cpp}、react_worker.cpp、tool_search_tool.{h,cpp}、skill_search_tool.{h,cpp}、单测）一次改完。
- **接口扩展**：`TurnState` 新增 `seedActiveSubset`（置 `activeIsFullPool_=false`，V2 findRelevant 子集种入路径）+ skill 侧 5 个对称方法。**不**加 `loadSkill`/`getLoadedSkills`（tool/skill load 不对称：tool 的 Tier2 是延迟态 `loadedTools`、skill 的 Tier2 是无状态一次性 `GetSkillInstructions` 当轮生效）。`SessionEntry` 加 `skillActiveSet` 字段、`TurnStateProxy` 加 `skillActiveIsFullPool_` flag。
- **Invoke 入口重写**（`react_worker.cpp`）：按 §5.4.1 条 6 降级判定表的 4 行严格分支——SELECTIVE 模式跑 `findRelevant`，按 per-side 比较结果（`rr.tools==pool`/`rr.skills==skillPool`）决定走 `seedActive`/`seedActiveSubset`（tool 侧）+ `seedSkillActive`/`seedSkillActiveSubset`（skill 侧）。返空 / 异常 / 解析失败 → 双侧 `seedActive(pool)` 退化 progressive。progressive 模式直接双侧 `seedActive(pool)`。
- **`SkillEngine::GetSkillCatalog` 重载**：保留无参版本（disabled 模式全量渲染，V1 行为零回归）+ 新增 `GetSkillCatalog(const std::set<std::string>& visibleSkillNames)` by-subset 渲染（progressive/selective 用，镜像 `ResourceManager::GetToolCatalog`）。
- **`skill_search` 短路 + 实召回**：`SkillSearchTool` 构造加 `TurnState*` + `CapabilitySelector*` 参数。search action 按 `isActiveFullSkillPool()` 短路（true → "No recall needed"，false → 走 `CapabilitySelector::findRelevant` 真召回）。load action 不动（skill Tier2 无延迟态）。`RegisterBuiltinTools` 工厂同步传 `ctx.turnState` + `ctx.capabilitySelector`。
- **`tool_search` 实召回**：`ToolSearchTool` 构造加 `CapabilitySelector*` 参数。search action 非短路分支调 `CapabilitySelector::findRelevant` 真召回（替代 V1 桩 `TurnState::search()`）。
- **`ToolBuildContext` 加 `capabilitySelector` 字段**（forward decl `class CapabilitySelector;` in `resource_manager.h`）：`AgentWorker::ExecuteTool` 在 `IsProgressiveDisclosureActive()` 时填 `ctx.capabilitySelector = capabilitySelector_.get()`；disabled 模式填 nullptr（让 skill_search 走 V1 substring fallback）。
- **默认 `toolDisclosureMode` 改为 `SELECTIVE`**（`include/types.h`）：V2 findRelevant 已实现，selective 真正可用，出厂默认启用。
- **`AgentWorker` 构造器 SELECTIVE fallback `LOG(WARN)` 删除**（条 2）：V1 因 findRelevant 未实现而加的告警，V2 不再需要。AUTO 的告警保留（仍 v2 未实现）。
- **`SetSkillEngine` 同步重建 `capabilitySelector_`**：因 SkillEngine 是 Agent-scoped、构造晚于 AgentWorker，构造时先 nullptr、`SetSkillEngine` 调用时重建 `CapabilitySelector(config_, engine.get())`。

## 行为变更与升级指南

### ⚠️ 性能影响

V2 默认 `SELECTIVE` 模式下，每个 user-turn 起点会跑一次 `findRelevant` LLM 调用（+1 LLM call/turn），用于从工具/技能池中召回最相关的子集种入 active set。该调用复用主 `modelConfig`，需要 API Key 与网络连接。

### 升级路径

- **小规模 agent（< ~20 工具）**：全量完整 schema 通常装得下上下文预算，无需召回。在 `AgentConfig` 中显式配置 `toolDisclosureMode = "disabled"` 跳过 +1 LLM 调用、行为回退 V1。
- **中等规模（~20–100 工具）**：完整 schema 装不下、但 name+desc 全量装得下。配置 `toolDisclosureMode = "progressive"`，主模型自选 `tool_search load` 哪个工具，0 额外调用。
- **大规模（~100–1000 工具）**：name+desc 也装不下。保持默认 `selective`，每 turn +1 LLM 调用召回 top-N，turn 中途 search action 走真召回补漏。

### 配置示例

```json
{
  "toolDisclosureMode": "selective",
  "alwaysOnTools": ["read_file"],
  "toolSchemaTokenBudget": 4096,
  "toolCatalogTokenBudget": 2048
}
```

`auto` 模式仍是占位（§10 TODO），遇到会按 `disabled` + 告警处理，后续按 budget 阈值自动判定的实现待 v3+。

### 依赖与兼容

- 无新增三方依赖；`CapabilitySelector` 复用现有 `ResourceManager` + `Model` + `SkillEngine`。
- `ToolSelector` API 完全删除，无迁移路径——V1 没有生产代码消费它的选择方法，仅 4 处 `AddToolToPool`/`RemoveToolFromPool` 镜像调用维护影子 pool，已随类一并删除。
- `ToolTurnState` 接口名变更：消费点全在仓内（`include/session_manager.h` 与 `include/resource_manager.h` 仅 forward decl，外部不构造），无下游影响。

## 框架变更

### 运行时与会话管理

- `AgentWorker` 基类新增 `std::unique_ptr<CapabilitySelector> capabilitySelector_` 成员，构造时初始化、`SetSkillEngine` 时重建。
- `SessionEntry` 加 `std::set<std::string> skillActiveSet` 字段（per-session 宿主、per-turn reset）。
- `SmWorkerEnv::GetCurrentTurnState()` 返回 `TurnState*`（接口与 proxy 重命名同步）。

### Agent 与记忆

无变更。

### 工具与技能

- `ToolSearchTool` 构造加 `CapabilitySelector*` 第三参数。
- `SkillSearchTool` 构造加 `TurnState*` + `CapabilitySelector*` 第二、三参数。
- `ResourceManager::RegisterBuiltinTools` 中 `skill_search` 工厂同步传 `ctx.turnState` + `ctx.capabilitySelector`。
- `SessionManager::Initialize`/`ReloadAgent` 中 `tool_search` 工厂同步传 `ctx.capabilitySelector`。

### MCP

无变更。

### 配置

- `AgentConfig::toolDisclosureMode` 默认值 `DISABLED` → `SELECTIVE`。
- 其他配置字段（`toolSchemaTokenBudget`/`toolCatalogTokenBudget`/`alwaysOnTools`）不变。
