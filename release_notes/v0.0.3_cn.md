# 版本 v0.0.3

## 概述

v0.0.3 相比 v0.0.2 在工具/技能的渐进披露能力上有较大演进：

- 落地 round5 渐进披露设计文档的 V2 与 V3 两阶段：V2 实现 `findRelevant`（LLM-backed capability recall）让 `selective` 模式真正启用；V3 把 `auto` 模式从占位变成真档位——构造期惰性解析 budget→三档（DISABLED/PROGRESSIVE/SELECTIVE）。
- 工具/技能池数量级从 ~16 builtin + MCP 扩到 skill-hub 量级（>1000）时，全量 schema 常驻不可持续；v0.0.3 引入 Tier 1 name+desc catalog + Tier 2 完整 schema 按需 load + findRelevant turn 起点召回 + tool_search/skill_search 中途补召回的四层渐进披露机制。
- 工具选择机制替换：废弃 V1 的 `ToolSelector`（选择方法是桩、数据通道只持 name），新建 `CapabilitySelector`（LLM-backed、按 name 经 ResourceManager 取 desc、不攒死副本）。
- 默认 `toolDisclosureMode` 从 V2 起改为 `SELECTIVE`（每 turn +1 LLM/turn 召回开销），用户可显式回退 `disabled` 跳过该开销；`auto` 模式作为 opt-in 选项（不配 budget 时降级 DISABLED、零额外开销）。

## 重点更新

### 框架层面

- **V2 — `CapabilitySelector` + `TurnState` 重命名**：新建 `CapabilitySelector`（`src/core/capability_selector.{h,cpp}`）做 LLM-backed capability 召回；废弃 `ToolSelector` 及其单测；`ToolTurnState` 重命名为 `TurnState`（文件 `tool_turn_state.h` → `turn_state.h`、proxy 同步），接口扩 `seedActiveSubset` + skill 侧 5 个对称方法；`SkillEngine::GetSkillCatalog` 加 by-subset 重载；`skill_search` 加 `TurnState*` + `CapabilitySelector*` 参数、search action 短路 + 实召回。
- **V2 — Invoke 入口解法 X + SELECTIVE 收敛**：`react_worker.cpp` 入口按 §5.4.1 条 6 降级判定表的 4 行严格分支（per-side 比较结果决定 `seedActive`/`seedActiveSubset`）；删 V1 的 SELECTIVE fallback `LOG(WARN)`。
- **V3 — AUTO 模式 budget→三档惰性解析**：`AgentWorker` 加 `mutable ToolDisclosureMode effectiveMode_` + `mutable std::once_flag resolveOnce_`，首调 `IsProgressiveDisclosureActive()` 时 `std::call_once` 惰性解析；`GetEffectiveMode()` public accessor；`ResolveByBudget()` 取数段 + `ResolveModeByTokenBudget()` 判定段 free function；`ContextEngine::EstimateTokens` 从 private 提 public 供复用。
- **V3 — Invoke seed 与注册站点读 effectiveMode_**：`react_worker.cpp:242` 改 `GetEffectiveMode() == SELECTIVE`；`session_manager.cpp:358/1016` 注册条件扩 `|| AUTO`；构造器删 AUTO `LOG(WARN)`。

## 框架变更

### 运行时与会话管理

v0.0.2 引入 `SessionManager` 作会话感知运行时；v0.0.3 在此基础上为 `AgentWorker` 加入 AUTO 模式惰性解析能力：

- `AgentWorker` 基类新增 `std::unique_ptr<CapabilitySelector> capabilitySelector_` 成员（V2，构造时初始化、`SetSkillEngine` 时重建）+ `mutable ToolDisclosureMode effectiveMode_{config_.toolDisclosureMode}` + `mutable std::once_flag resolveOnce_`（V3）。
- `IsProgressiveDisclosureActive()` 改为 `std::call_once` 惰性解析（V3），仅 AUTO 触发、PROG/SEL 跳过；新增 `GetEffectiveMode()` public accessor（V3，调 `IsProgressiveDisclosureActive()` 触发副作用后返 `effectiveMode_`）。
- `SessionEntry` 加 `std::set<std::string> skillActiveSet` 字段（V2，per-session 宿主、per-turn reset）。
- `SmWorkerEnv::GetCurrentTurnState()` 返回 `TurnState*`（V2，接口与 proxy 重命名同步）。
- `react_worker.cpp` Invoke 入口重写为解法 X（V2，按 §5.4.1 条 6 降级判定表 4 行严格分支）+ seed 分支改读 `GetEffectiveMode()`（V3，AUTO 解析成 SELECTIVE 后能走 findRelevant 路径）。

### Agent 与记忆

无变更。

### 上下文引擎

- `ContextEngine::EstimateTokens` 从 private 提为 public static（V3，供 `ResolveByBudget` 复用做 token 估算，纯 utility、不破坏封装语义）。其余不变。

### 模型与工具调用

无变更。`Model`/`OpenAIModel`/`AnthropicModel` 在 v0.0.2 已具备结构化响应能力，v0.0.3 复用主 `modelConfig` 做 `findRelevant` 召回（不引入独立便宜召回模型）。

### 工具系统

v0.0.2 引入结构化 schema 和会话级构造；v0.0.3 引入渐进披露的四层机制：

- 新建 `CapabilitySelector`（`src/core/capability_selector.{h,cpp}`）：LLM-backed capability 召回，`findRelevant(rawQuery, sessionContext) -> CapabilitySelection{tools, skills}`，复用主 `modelConfig`、按 name 经 `ResourceManager`/`SkillEngine` 取 desc（不攒死副本）。失败 / 返空 → 返空 `CapabilitySelection`，由 Invoke 入口识别为降级触发条件。
- 废弃 `ToolSelector`（`src/tools/tool_selector.{h,cpp}` + `unittest/test_tool_selector.cpp` 删除）：V1 双重缺陷——选择方法死（`return 1.0` 桩）、数据通道错（只持 name 不持 desc）。`AgentWorker::toolSelector_` 成员、4 处 `AddToolToPool`/`RemoveToolFromPool` 镜像调用一并删除。
- `ToolTurnState` → `TurnState` 重命名（文件 `tool_turn_state.h` → `turn_state.h`、proxy 同步），内部头不导出。接口扩 `seedActiveSubset`（置 `activeIsFullPool_=false`，V2 findRelevant 子集种入路径）+ skill 侧 5 个对称方法（`searchSkill`/`getSkillActiveSet`/`seedSkillActive`/`seedSkillActiveSubset`/`isActiveFullSkillPool`）。**不**加 `loadSkill`/`getLoadedSkills`——tool/skill load 不对称（tool Tier2 是延迟态 `loadedTools`、skill Tier2 是无状态一次性 `GetSkillInstructions`）。
- `SkillEngine::GetSkillCatalog` 重载：保留无参版本（disabled 模式全量渲染、V1 行为零回归）+ 新增 by-subset 重载 `GetSkillCatalog(const std::set<std::string>& visibleSkillNames)`（镜像 `ResourceManager::GetToolCatalog`）。`BuildPrompt` 调用方经 `workerEnv_->GetCurrentTurnState()` 读 skill active set、传 visible names；skill 侧无 alwaysOn 概念（FC 协议门控是 tool 侧约束、skill 是 prompt 文本引用、`skill_search` 工具本身即逃逸阀）。
- `skill_search` 加 `TurnState*` + `CapabilitySelector*` 参数；search action 按 `isActiveFullSkillPool()` 短路（true → "No recall needed"、false → 走 `CapabilitySelector::findRelevant` 真召回）；load action 不动（skill Tier2 无延迟态）。
- `tool_search` 加 `CapabilitySelector*` 参数；search action 非短路分支调 `CapabilitySelector::findRelevant` 真召回（替代 V1 桩 `TurnState::search()`）。
- `ToolBuildContext` 加 `capabilitySelector` 字段（forward decl `class CapabilitySelector;` in `resource_manager.h`）；`AgentWorker::ExecuteTool` 在 `IsProgressiveDisclosureActive()` 时填 `ctx.capabilitySelector = capabilitySelector_.get()`，disabled 模式填 nullptr（让 skill_search 走 V1 substring fallback）。
- `ResourceManager::RegisterBuiltinTools` 中 `skill_search` 工厂同步传 `ctx.turnState` + `ctx.capabilitySelector`；`SessionManager::Initialize`/`ReloadAgent` 中 `tool_search` 工厂同步传 `ctx.capabilitySelector`（V2）；V3 注册条件扩 `|| AUTO`（AUTO 下一律注册 tool_search，靠运行时短路兜底——解析成 DISABLED 时多余注册属"模型看得到却用不上"的轻量退化）。

### MCP

无变更。MCP 运行时增量在 V3 惰性解析后不实时改档，靠 `ReloadAgent` 兜底——V3 已知限制。

### 配置与技能

- `AgentConfig::toolDisclosureMode` 默认值 V2 改为 `SELECTIVE`（v0.0.2 时是 `DISABLED` 占位）；V3 `AUTO` 枚举注释从"Reserved: maps to disabled + warning"改为"Budget-driven: resolves to DISABLED/PROGRESSIVE/SELECTIVE via ResolveByBudget (§5.4.1)"。
- `toolSchemaTokenBudget`/`toolCatalogTokenBudget` 字段在 v0.0.2 已存在（默认 0），v0.0.3 V3 起被 `ResolveByBudget` 消费：注释从"for future AUTO"改为"consumed by auto's ResolveByBudget (§5.4.1); 0 = unused (该档不参与判定)"。字段类型保持 `int`。
- 其他配置字段（`alwaysOnTools` 等）不变。

### 兼容性说明

- `ToolSelector` API 完全删除、无迁移路径——V1 没有生产代码消费它的选择方法，仅 4 处 `AddToolToPool`/`RemoveToolFromPool` 镜像调用维护影子 pool，已随类一并删除。

- `ContextEngine::EstimateTokens` 可见性从 private 提为 public——纯 utility、不破坏封装语义，外部消费点（V3 `ResolveByBudget`）复用做 token 估算。

## 行为变更与升级指南

### ⚠️ 性能影响

v0.0.3 起出厂默认 `toolDisclosureMode = SELECTIVE`，每个 user-turn 起点跑一次 `findRelevant` LLM 调用（+1 LLM call/turn），用于从工具/技能池召回最相关的子集种入 active set。该调用复用主 `modelConfig`，需 API Key 与网络连接。

### 升级路径（按工具池规模选档）

- **小规模（< ~20 工具）**：全量完整 schema 装得下，无需召回。显式配 `toolDisclosureMode = "disabled"` 跳过 +1 LLM、行为回退 v0.0.2。
- **中等规模（~20–100 工具）**：完整 schema 装不下、但 name+desc 全量装得下。配 `toolDisclosureMode = "progressive"`，主模型自选 `tool_search load` 哪个工具，0 额外调用。
- **大规模（~100–1000 工具）**：name+desc 也装不下。保持默认 `selective`，每 turn +1 LLM 调用召回 top-N，turn 中途 search action 走真召回补漏。
- **不确定规模（auto 自适应）**：配 `toolDisclosureMode = "auto"` + `toolSchemaTokenBudget`（经验阈值如 4096）+ `toolCatalogTokenBudget`（经验阈值如 2048）。V3 惰性解析按 pool 实际 token 自动抬升档位；**不配 budget（两字段默认 0）则 auto 解析成 DISABLED**——零 +1 LLM 开销，与 v0.0.2 的"auto→disabled+WARN"行为零回归（只是 WARN 已删）。

### 配置示例

```json
{
  "toolDisclosureMode": "selective",
  "alwaysOnTools": ["read_file"],
  "toolSchemaTokenBudget": 4096,
  "toolCatalogTokenBudget": 2048
}
```

### 依赖与兼容

- 无新增三方依赖；`CapabilitySelector` 复用现有 `ResourceManager` + `Model` + `SkillEngine`。
- `auto` 模式在 v0.0.2 是占位（遇 `auto` 落到 `disabled` + 告警）；v0.0.3 V3 起变成真档位，构造器 WARN 删除、首调 `IsProgressiveDisclosureActive()` 时惰性解析。

### 已知限制

- **MCP 运行时增量不实时改档**（V3）：运行时 `RegisterMcpTools` 加的工具若发生在惰性解析**之后**（`call_once` 已跑过、`once_flag` 已置位）则不纳入本次 turn 的档位——要等下次 `ReloadAgent` 重解析才纳入。这是惰性解析（非每 turn 解析）的已知折中，靠 `ReloadAgent` 兜底。若实测 MCP 运行时增量频繁、档位需要实时跟，V3 之后可加"解析失效信号"（MCP 注册后重置 `once_flag` 强制重解析）——本版本不做、留为已知限制。
