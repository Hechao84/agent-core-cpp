# 版本 v0.0.4

## 概述

v0.0.4 相比 v0.0.3 聚焦 `web_search` 工具的反爬韧性。生产日志显示原设计下 DDG/Bing 在 IP 被搜索引擎限流后均不可用，且模型在 17s 内 3 次近似 query 硬刷进一步加剧封禁。v0.0.4 用六层防御解决"被反爬后仍能拿到结果"：

- DDG 端点从 `html.duckduckgo.com/html/`（必然触发 `anomaly.js`）切到 `lite.duckduckgo.com/lite/`；请求形态从 GET querystring 改为 POST 表单提交。
- 引擎回退按**查询语言路由**：含 CJK 字符走中文引擎链（Baidu 直连国内 IP → Sogou 经代理），纯 ASCII 走 Western 链（DDG → Wikipedia → Bing）。中文查询走中文引擎，从国内 IP 直连 Baidu 绕开 VPN 共享出口 IP 的封禁问题，且对中文新闻/财经查询覆盖更好；ASCII 查询走 DDG/Wiki/Bing，因为 Baidu/Sogou 的英文索引覆盖差。
- 重试策略修正为 **fail-fast on 真挑战**：仅在 curl 传输错误 / 429 / 503 时重试；`202/418/403` 与 body-marker 挑战一律不重试（重试只是把封禁坐实并升级）。
- 跨调用 per-engine 冷却（DDG 8s / Bing 15s / Wikipedia 1s / Baidu 5s / Sogou 8s），避免模型连续硬刷触发限流窗口。
- UA 从 per-query 切换改为 **per-process 固定**，避免"同 IP 多浏览器"的可疑指纹。
- 5 分钟结果缓存（`"<engine>|<query>"` keyed），命中跳过冷却 + 网络。
- 工具 description 明告诉模型不要同 turn 内对近似 query 反复 search——直击反爬触发的模型行为根因。
- 新增 `CurlRequest::noProxyHosts` 字段（`CURLOPT_NOPROXY`），让 Baidu 直连国内 IP 绕过 `HTTPS_PROXY` 环境变量。
- 修复 Sogou 解析器在 std::regex lookahead 下栈溢出崩溃（重写为不依赖 lookahead 的双 regex 按下标配对法）。

## 重点更新

### 框架层面

- **`web_search` 六层防御**：
  - **Layer 1**（请求形态伪装）：UA per-process 固定（5 个 Chrome / Firefox / Win / Mac / Linux UA 池、`std::random_device` 锁定）；DDG POST 表单提交；跨调用 per-engine 冷却。
  - **Layer 2**（fail-fast 重试）：`ShouldRetry` 仅在 curl 传输错误 / 429 / 503 时返 true；`202/418/403` 与 body-marker 挑战一律不重试。单次失败延迟从 ~9s 降到 ~1s。
  - **Layer 3''**（CJK 路由 + 中文搜索引擎）：
    - `ContainsCJK(query)` 检测查询是否含 CJK Unicode 字符（U+3000-U+9FFF / U+F900-U+FAFF / U+FF00-U+FFEF）。
    - CJK 查询 → Baidu（直连国内 IP）→ Sogou（经代理）。CJK 链到此停止——Wikipedia en 对 CJK 无覆盖、Bing 对 CJK 返垃圾结果（如对中文 query 返 Walmart 主页），跳过避免浪费 2-3s。
    - ASCII 查询 → DDG → Wikipedia → Bing（保持原行为）。
    - `IsBaiduChallenge` / `IsSogouChallenge` 新增：检测 `百度安全验证` / `百度验证` / `waptcha` / `safecheck` / `请输入验证码` / `网络不给力` / `/captcha/` 与 `antispider` / `用户您好` / `请输入验证码` / `/captcha/` / `sogou_vr_captcha` 等 marker。
    - `ParseBaiduResults`：`tn=baidurt` 模板返回**直接外部 URL**（不经 `baidu.com/link?url=` 重定向跳转）。要求锚点在 `<h3>` 包装内（任意 class，包括 `t` 与 `c-title t`）以过滤 Baidu 导航链接（preferences/login/news/hao123/vsearch）。
    - `ParseSogouResults`：扫描整 body 找 title 与 snippet 两类锚点，按下标配对（i-th title ↔ i-th snippet）。不使用 lookahead-based blockRe——std::regex 的 lookahead 用递归下降实现，在 Sogou 大 body 上会栈溢出（已通过 gdb backtrace `_M_dfs → _M_lookahead → _M_dfs` 递归到 SIGSEGV 确认）。
  - **Layer 4**（5 分钟结果缓存）：`WebSearchResultCache` 单例，`"<engine>|<query>"` keyed，TTL 300s，仅缓存成功 outcome。
  - **Layer 5**（工具 description 行为约束）：明告诉模型 issue ONE web_search per turn，对结果用 `web_fetcher` 取详情，不要同 turn 内近似 query 反复 search。错误消息尾部追加 IP-flagged 提示。
- **`CurlRequest` 扩三字段**：`referer`（`CURLOPT_REFERER`）+ `enableCookies`（`CURLOPT_COOKIEFILE=""` 启用 curl 内存 cookie 引擎）+ `noProxyHosts`（`CURLOPT_NOPROXY` 绕过 `HTTPS_PROXY`/`HTTP_PROXY` 环境变量）。前两者已有，`noProxyHosts` 新增。这是 `CurlClient` 的通用增强，非 web_search 专属。
- **纯函数化**：13 个自由函数声明在 `web_search_tool.h`（`IsDDGChallenge` / `IsBingChallenge` / `IsBaiduChallenge` / `IsSogouChallenge` / `ShouldRetry` / `ComputeBackoffMs` / `PickUserAgent` / `ContainsCJK` / `ParseDdgLiteResults` / `ParseBingResults` / `ParseBaiduResults` / `ParseSogouResults` / `ParseWikipediaResults`）；`WebSearchResultCache` 为类形式以便注入短 TTL 测试过期；重试循环 `HttpGetWithRetry` + 直连 helper `HttpGetOnce` / `HttpPostOnce` + per-engine 冷却 `CooldownBefore` 留在 `.cpp` 匿名命名空间内（端到端由 `integration_tests/smoke_web_search.cpp` 覆盖）。

## 行为变更与升级指南

- **`web_search` 失败模式**：CJK 查询走 Baidu 直连 + Sogou 经代理，被挑战即放弃返明确错误；ASCII 查询走 DDG + Wikipedia + Bing。最坏延迟约 15s（Baidu 1s + Sogou 1s 或 DDG 1s + Wikipedia 1s + Bing 1s + 各自冷却），但仅在 IP 被全面封禁时发生。
- **`web_search` 工具 description 变化**：模型现在看到的工具说明明告诉它不要同 turn 内对近似 query 反复 search。模型如忽略此约束仍硬刷，IP 仍会被封——这是模型行为问题，非工具问题。
- **`CurlRequest` 新增字段**：`referer`、`enableCookies`、`noProxyHosts` 均有默认值（空串 / false / 空串），现有调用方零改动；仅 `WebSearchTool` 启用。

## 已知的固有局限

所有 HTML 抓取类搜索引擎（DDG / Bing / Brave / Baidu / Sogou）都按 IP 限流，agent 出站 IP（无论是 VPN 代理出口 IP 还是直连国内 IP）在连续多次请求后都会被封禁。本设计的 Layer 1+2+5 大幅降低触发概率，但无法完全消除——频繁使用下仍会偶发"全部引擎失败"。若需"始终拿得到结果"，唯一稳健解是接入账号绑定的搜索 API（如 Brave Search API 免费档，按账号限流不按 IP），作为未来保险。
