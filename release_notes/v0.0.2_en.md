# Release v0.0.2

## Overview

v0.0.2 is a major evolution from v0.0.1: 

- `jiuwen-lite` has moved from a demo-oriented, mostly single-agent shape to a C++ Agent framework with a multi-session runtime, transport-layer decoupling, native function calling, JSON context persistence, runtime MCP management, and hot-reloadable configuration. 
- `jiuwenClaw` reference application has expanded into a complete sample application that includes CLI, HTTP REST/SSE, Web UI, Feishu channels, Agent configuration management, and MCP server management.

## Highlights

### Framework

- Added `SessionManager` as the main runtime entry point for per-session context isolation, per-session locking, and global concurrency control.
- Added native function calling support for OpenAI-compatible and Anthropic models, while retaining the prompt-only tool-calling fallback mode.
- Changed context persistence from Markdown files to JSON files, and added support for persisting tool-call metadata.
- Added Dream memory consolidation based on interaction history and idle-session detection.
- Refactored the MCP module to support runtime configuration loading, connect/disconnect, tool registration, and live-agent tool synchronization.
- Added Agent configuration persistence, JSON serialization, and an optional configuration watcher to support hot-reloading Agent configuration.
- Added session-scoped `todo_*` and `ask_user` tools.

### jiuwenClaw

- Added an HTTP REST/SSE server and built-in Web UI.
- Added Feishu/Lark WebSocket channels and channel management capabilities.
- Added management APIs for Agent configuration, skills, MCP servers, and more.
- Added application-level MCP server persistence and runtime synchronization.
- The CLI now supports session switching, configuration inspection, and runtime reload.
- Split the HTTP and Feishu adapters into standalone static library targets so they can be reused or replaced more easily.

## Framework Changes

### Runtime and Session Management

In v0.0.1, Agents were mainly used by directly calling `Agent::Invoke(query, callback)`. 

v0.0.2 introduces `SessionManager`, making the runtime model session-aware:

- Each session has its own `ContextEngine`.
- Calls within the same session are serialized to avoid concurrent writes to the same session context.
- `AgentConfig::maxConcurrentSessions` controls the global number of concurrent sessions.
- Reserved sessions are defined for default chat, heartbeat tasks, cron tasks, and similar uses.
- `ChannelMessage` and the session-key derivation mechanism support routing sessions from different transport layers.
- When configuration changes, the live agent can be rebuilt through `ReloadAgent`.

### Agent and Memory

`Agent` now includes history and Dream memory components:

- Added `HistoryStore` to record interaction history with cursors.
- Added `DreamProcessor` for long-term memory consolidation.
- Added session active/idle notifications.
- Replaced the old direct memory operation flow with automatic memory consolidation.
- `DreamConfig` controls limits such as history batch size, iteration count, tool-result length, and memory file size.

### Context Engine

Context persistence has changed significantly:

- `ContextConfig::StorageType::MARKDOWN_FILE` was replaced with `JSON_FILE`.
- JSON storage now persists role, content, tool calls, tool call IDs, and tool names.
- SQLite storage now supports the same richer message structure.
- Shared storage logic was extracted into `ContextStorageBase`.
- LLM context construction now supports a more complete message structure for tool calls and tool responses.

### Models and Tool Calling

The model abstraction has been upgraded from plain text responses to structured responses:

- Added `ToolCall`, `ToolSchema`, and `ModelResponse` in `include/model.h`.
- `Model::Format` now accepts tool schemas.
- `Model::Invoke` now returns `ModelResponse`, which includes both text and tool calls.
- OpenAI-compatible streaming responses support incremental assembly of `tool_calls`.
- Anthropic streaming responses support `tool_use` and `tool_result` message formats.
- `ModelConfig::useNativeFunctionCalling` can enable the provider-native protocol, or fall back to prompt-only ReAct.
- `ModelConfig::extraParams` supports forwarding common model request parameters.
- The fallback parser supports JSON-style tool calls and classic ReAct `Action` syntax.

### Tool System

The tool layer now supports structured schemas and session-scoped construction:

- `Tool::GetJsonSchema()` can generate a JSON Schema from tool parameters.
- `ResourceManager::BuildToolSchemas()` generates the schemas required for native function calling.
- `ResourceManager::RegisterSessionTool()` can register tools that require session resources.
- Added session-scoped tools:
  - `todo_create`
  - `todo_complete`
  - `todo_insert`
  - `todo_remove`
  - `todo_list`
  - `ask_user`
- The `web_search` tool was enhanced to try multiple backends and provide clearer failure feedback.

### MCP

MCP support has been refactored from a simple registration path into a runtime-managed module:

- Moved the MCP implementation to `src/mcp/`.
- Added `MCPConnection` and `MCPConfigManager`.
- Added `McpServerConfig` to the public types.
- Added runtime APIs in `ResourceManager` to load, register, unregister, and inspect MCP servers.
- MCP tools are tracked separately so they can be removed synchronously when a server disconnects.
- MCP server connection failures no longer prevent the rest of the framework from starting.

### Configuration and Skills

- Added JSON serialization/deserialization for `AgentConfig`.
- Added `AgentConfigStore` for persistent override configuration in `./data/agents.json`.
- Added `ConfigWatcher` for polling-based reload workflows.
- Added the public skill type `include/skill.h`.
- `Agent` now exposes APIs for listing skills and reading skill details.
- The configuration schema is designed for multiple Agents, while the current runtime runs one live agent at a time through `SessionManager`.

### Compatibility Notes

- ReAct is the actually implemented execution mode in v0.0.2.
- `AgentWorkMode::PLAN_AND_EXECUTE` and `AgentWorkMode::WORKFLOW` are not implemented yet; support may be considered in the future.
- Markdown context storage has been replaced with JSON file storage.
- Applications that directly instantiate `Agent` are recommended to migrate to the `SessionManager` runtime model.

## jiuwenClaw Changes

### Application Architecture

`jiuwenClaw` has been refactored into a single-entry reference application that can run in the following modes:

- CLI-only assistant.
- CLI + HTTP server + configured channels.
- Daemon mode with only the HTTP server and channels.
- Server mode with an optional configuration watcher.

### HTTP REST, SSE, and Web UI

Added an HTTP server adapter and built-in Web UI, covering chat, sessions, and runtime management:

- Chat and streaming chat APIs.
- Session CRUD and session history APIs.
- Agent configuration APIs.
- Channel management APIs.
- Skill list/detail APIs.
- MCP server management APIs.
- `ask_user` answer API.
- SSE events distinguish streaming tokens, status updates, tool calls, tool responses, user clarification questions, and completion events.

### Feishu and Channel Management

Added Feishu/Lark integration and abstracted channels into application-level resources that can be persisted and reconciled at runtime:

- Feishu WebSocket bot adapter.
- Persistent channel definitions in `./data/channels.json`.
- Runtime channel apply/remove/reconcile service.
- Channel management through the Web UI and REST API.

### MCP Server Management

Added application-level MCP persistence and UI/API integration:

- Added `McpServerManager`.
- MCP server definitions are persisted in `./data/mcp_servers.json`.
- Supports APIs to create, update, delete, and reload MCP servers.
- MCP server changes automatically synchronize tools into the live agent.
- When an MCP server is deleted, the corresponding server ID is cascaded out of Agent configurations.

### CLI Improvements

The CLI adds runtime management commands:

- `/session <id>`: switch sessions.
- `/sessions`: list sessions.
- `/reload`: reload agents and channels.
- `/reload agent [<id>]`: reload the specified Agent configuration.
- `/reload channels`: reload channel configuration.
- `/config show [<id>]`: inspect the effective configuration.

### Prompt and Model Updates

- Added `MEMORY.md` for Dream memory consolidation.
- Prompt rendering supports injecting long-term memory and the current session todo state.
- OpenAI-compatible models support injecting vendor-specific extended parameters through `extraParams`.

### Build and Packaging

- Split the HTTP and Feishu adapters into standalone static library targets.
- Copy Web UI files after building `jiuwenClaw`.
- Updated Linux and Windows build scripts and packaging output.
- Added/updated unit tests for configuration and context behavior, as well as smoke tests for model formatting and session tools.

## Upgrade Notes

- Migrate `Agent::Invoke(query, callback)` calls to `GetSessionManager().Invoke(sessionId, query, callback)`.
- Replace `ContextConfig::StorageType::MARKDOWN_FILE` with `JSON_FILE`.
- If native function calling is disabled, review tool prompts; fallback mode expects JSON tool calls or classic ReAct `Action` / `Action Input` syntax.
- If you want to manage configuration through the Web UI/API, place runtime override configuration in `./data/agents.json`.
- If you want runtime MCP management, place MCP definitions in `./data/mcp_servers.json`.
